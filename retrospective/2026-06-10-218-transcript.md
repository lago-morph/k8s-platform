# Session capture — 2026-06-10 (ADR-0010 keystone session)

Companion to [`2026-06-10-218.md`](./2026-06-10-218.md), the retrospective
for the same session. That file *processes* the session (lessons,
remedies); this one *preserves* it — the ideas as they were exchanged,
grouped by topic, with the losers, hedges, and reversals kept.

**What this is.** A capture of the ideas exchanged in the session that
produced PRs #218 and #219, grouped by topic rather than by time. It
holds what was said — including suggestions that were modified,
withdrawn, or left unaddressed — so the whole context can be picked up
again later. Both voices are compressed; key phrases are quoted.

**What this is not.** Not a design, not a prioritized list, not a set of
decisions. The only decisions J explicitly made were process-shaped: what
to work on ("Keystone only"), to ratify ADR-0010 and implement, to merge,
to write the next-session prompt, to retrospect, to implement the retro's
recommended remedies "keeping in mind we need to not accrete things," and
to merge again. Everything else J said, however firmly, was an opinion at
that point in time. Lines marked *stated position* are the ones put most
firmly; they are not settled.

**Source caveat.** The agent's context was compacted partway through the
session. Everything before J's "Keystone only" answer — the forensics
round-2 work, PR #217, the instruction-surface restructure, J's merging of
PRs #210–#213 — survives only as a summary in the agent's context and is
captured here at summary fidelity (§12). Everything from "Keystone only"
onward is captured from full context. The session was resumed on
2026-09-13 to make this capture; the repo had moved on since (e.g.
`argocd/apps/spoke/keycloak.yaml` changed on disk), and none of that later
work is in this capture.

## 4. The mechanism (ADR-0010) and how it moved under review

- **A:** proposed: facts ride the spoke's ArgoCD cluster Secret as
  `k8-platform.io/*` annotations; spoke apps become ApplicationSets whose
  cluster generators template them into helm values. Alternatives A
  rejected in the ADR: literal ConfigMap (infeasible, §3); bootstrap
  `ignoreDifferences` ("keeps the banned pattern"); ApplicationSet plugin
  generator ("strictly heavier"); templated plain Applications ("no
  templating mechanism; rejected on fact").
- **A:** first draft claimed a four-fact contract, "nine" apps, a seamless
  cutover, alloy folding into the same ApplicationSets, and kubeconform
  verification.
- **Two adversarial reviewers (A-dispatched, tree-grounded):** returned 5
  BLOCKER + 7 MAJOR. In A's words to J: "three of my claims don't survive
  the tree." Specifically —
  - kubeconform claim was "hollow": no ApplicationSet schema was ever
    fetched; `--ignore-missing-schemas` would silently skip the new kind.
  - cutover is "genuinely non-atomic": bootstrap prunes the old
    Applications, generated same-named ones re-sync fresh.
  - alloy "structurally cannot share an ApplicationSet with the spoke
    apps" (different project, different destination) — and auto-008 had
    explicitly rejected the cluster generator over exactly that hazard.
  - keycloak's DB host/port "don't reduce to cluster facts at all" (third
    XR).
  - `region` "has no surfaced producer source" — A's EnvironmentConfig
    claim was false.
  - plus: the argo CRD store pinned to a different ArgoCD version than
    deployed; `SyncWaves=true` in bootstrap is not a real option; app name
    vs destination name conflated; five test files break.
- **Draft → revised (moved by A, on review):** contract grew to five facts
  with `subdomain` added and declared "per-Secret complete"; per-add-on
  ApplicationSets with selector scoping (base add-ons fan out to all
  spokes; keycloak/kps/loki/alloy pin `short-name=spoke`); alloy in its
  own hub-pinned set with the auto-008 F1 reversal recorded; honest
  cutover section; ADR-0005 marked superseded; `missingkey=error`;
  `preserveResourcesOnDeletion`; waves copied onto generated Applications;
  external-dns values file selected by short-name.
- **Keycloak DB host/port — scoped out, then re-corrected.** A's revised
  ADR said they'd ride the keycloak-db Secret via chart `existingSecret`
  host/port keys, "verify at implementation; fallback: extend contract."
  During implementation A found the repo already records the Bitnami
  chart "has no existingSecret host/port key." A rewrote the ADR text to
  state that as a repo-verified fact and to name two PR-2 options
  (`extraEnvVarsSecret` vs contract extension) for PR-2 to decide.
  *Open — deferred to PR-2 by A.*
- **Security finding (reviewer, kept by A):** the cluster Secret becomes
  "credential + fact bus"; a single writer of record and RBAC must be
  named in PR-2; an ESO template bug could clobber ArgoCD's connection
  `config`, not just stale a fact. *Open — deferred to PR-2.*
- **J:** asked to ratify; chose "Ratify + implement (Recommended)." J did
  not comment on any individual review finding. *Stated position:* the
  mechanism, as A framed it in the question — cluster-Secret annotations
  + ApplicationSets, superseding ADR-0005's ConfigMap corollary, keycloak
  DB via the Secret path, implement the static half now.

## 7. "Why is applicationset_v1alpha1.json 24000 lines?"

- **J:** asked the question directly.
- **A:** measured rather than guessed: `application_v1alpha1.json` is
  5,840 lines; the ApplicationSet schema contains 25 `syncPolicy`
  occurrences and 48 `valuesObject` — "~25 inlined copies of the entire
  Application spec." Sources of the copies: `spec.template` (1), a
  per-generator `template` override on each of 10 generator types (10),
  and `matrix`/`merge` nesting child generators one level deep (~14).
  Root cause: "OpenAPI schemas inside CRDs cannot use `$ref`." A called
  the bulk "load-bearing" because it is what lets kubeconform validate
  `spec.template.spec.sources[].helm.valuesObject`.
- **J:** did not follow up. *Unaddressed.*
