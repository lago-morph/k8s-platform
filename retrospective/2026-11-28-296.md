## Part 1 — what happened

### Phase 1 — Orientation, then sizing and single-sourcing (#277)
The session opened on "what does done mean for step 3?". The answer was in the
beads epic: everything was closed except the owner's human bring-up (kp-2al.10).
The owner then asked for 2× m5.large and a Kubernetes version check, which
exposed that the hub had been on 1.35 since May while the spoke stayed on 1.32
(extended support), contradicting the XRD's own comment. The owner's follow-up,
"one place for node types, one place per cluster for versions", produced the
EnvironmentConfig design (ADR-071d60bd01). An honest check before merge mattered: the
local render showed a missing `nodeInstanceTypes` key would compose no
NodeGroup, and after the merge a second render with observed resources proved
an *existing* NodeGroup is kept. A hypothesis voiced as a risk was retired with
evidence, not left hanging.

### Phase 2 — The owner's bring-up and the hollow verdict (#278)
The owner ran the bring-up page by hand on a fresh account (clean build #10)
while asking pointed questions: the console URL showed `***` (GitHub masks
any secret's value, and the region was a secret), and Live verify showed
"RELAY UNREACHABLE / tunnel flake". Reading build #9's log revealed the same
four skips, and two sibling checks already said the true cause: the scoped
role has no `ssm:StartSession`. Twelve of 29 checks had never run in CI; their
coverage was manual agent runs last done on build #7. The owner ran the 12
by hand (12/12 PASS) and ruled it a defect. #278 made CI a full verdict
(ADR-4d858140f6): 29/29 in 1m36s on the owner's platform, before merge,
legitimately green because tests/live changes are not GitOps-delivered.

### Phase 3 — Planning step 3's tail and inventing step 3.1
The owner added Kubernetes 1.37, installer scripts, an ASM-stored Argo CD
password, unreachable logs, version currency, pinning and Keycloak on the
official image; then split it: version/pinning work became step 3.1 (`kp-uvy`),
not blocking step 3, and SSO later became step 3.2 (`kp-sk6`). Two enrichment
subagents researched every 3.1 bead (≈30 child beads, real release data); one
found EKS module v21 is blocked by the owner's provider freeze, another that
`BD_VERSION` in `versions.env` is read by nothing.

### Phase 4 — Six parallel implementation agents (#279–#291)
Six worktree agents each took one bead and returned a PR: K8s 1.37 + kind
v0.33, kubeconfig script, Cognito script, ASM Argo CD password, control-plane
logs, region-as-variable. Briefs that worked named the exact files, the
test-first rule, files *not* to touch (because another agent owned them), and
the expected red gate. Every agent hit the same snag (no beads database in a
fresh worktree, kp-zab.9). Two findings changed step 3: the ops box had no spoke
access (kp-2al.49) and crashed-pod logs are unrecoverable (moved to step 5 by
the owner).

### Phase 5 — The permission block and the merge treadmill
`gh workflow run chainsaw.yml` was refused twice by the auto-mode classifier
("Destructive or Unwanted Actions"). The owner asked which rule fired. The
transcript's `permissionDecision.classifierCategory` gave only a category;
timestamps of settings backups showed the first block predated the owner's
customization and the second ran under it; only "Blind Apply" fit. The owner
removed it and the identical dispatch went through, confirming both the rule
and that settings hot-reload. Merging then became a treadmill: every merge to
`main` forced rebases (the `tests/unit/run.sh` registration hunk conflicted
almost every time), and Chainsaw verify keys on the exact commit, so each
rebase meant a fresh 15-minute chainsaw run. Stacking #283 → #284 → #288 so one
chainsaw run covered three PRs cut that cost.

### Phase 6 — Test build on 478728046113: what only a build could show
The driver died on `HOME: unbound variable` under `ssm send-command` (#289).
The ops box and base workflows raced on a fresh backend when dispatched
together (kp-zab.18). Hub-side everything matched: 1.37, m5.large, pinned
add-ons, 7-day logs, TLS 1.0/1.1 refused (after discarding a false result:
plain `openssl -tls1_1` fails client-side). Then convergence failed:
**Argo CD 2.10 cannot manage Kubernetes ≥ 1.35** (`terminatingReplicas`).
The agreed fallback (keep 1.35) was checked before being recommended and found
invalid: the field is on by default from 1.35. The owner chose a single jump to
Argo CD 3.6 (ADR-b12417e75f); an agent reproduced both failures on kind 1.37
with 2.10 and cleared them with 3.6. Upgraded in place, the platform converged
after a gate re-sync (tracking label → annotation), and Live verify read
30/30, including the new Argo CD password check. Two `A && B || C` lint failures
came from CI's shellcheck 0.9.0 flagging what local 0.11.0 accepts; running the
suite with a dockerised 0.9.0 shim stopped the round-trips.

### Phase 7 — Clean build #11 and closing step 3 (#293–#296)
On the owner's fresh account (599626541016) the build from `main` needed no hand:
the `HOME` fix proven, convergence in 64 s with no gate re-sync (fresh Argo CD
3.6). Live verify right after BRING-UP COMPLETE read 29/30: the federation
check met EKS's documented OIDC-association lag. A re-run 12 minutes later
read 30/30, confirming the diagnosis, and #293 made the check wait (bounded,
refreshing the short-lived token). Records (#294), README (#295, it had not
changed since June), and step 3.2 (#296) closed the session; step 3 epic
closed 57/57.

## Part 3 — remedy proposals (classified per `ai/LESSONS.md` §3)

Per the 2026-06-10 amendment, no per-rule AGENTS-MD files; each lesson is
classified (a) mechanical check, (b) one-line judgment rule, (c) structural
proposal, (d) observation.

1. **(a) — adopted this session.** *CI verdict skipped 12 checks silently.*
   Strict skips + cluster identity + shared tunnels (#278); relay-hygiene lint
   (no `--exec` discards stderr; relay checks declare identity). Grounded in
   build #10's 17/29.
2. **(a) — adopted.** *Kind ran a different Kubernetes than the hub for months.*
   `test_chainsaw_kind_config.sh` now holds kind's node minor == hub
   `cluster_version` (red on the old main: 1.32 vs 1.35).
3. **(a) — adopted.** *Pinned component outside its tested Kubernetes range.*
   `test_argocd_kubernetes_support.sh` checks Argo CD's upstream tested range
   covers every cluster version. **Proposal:** generalise it to every chart
   with a published support matrix in step 3.1 (it would have flagged Argo CD
   2.10 before a build did).
4. **(a) — proposed (kp-uvy.3.3).** *shellcheck version skew (CI 0.9.0 vs local
   0.11.0) let SC2015 through twice.* Pin one shellcheck version in CI and
   `sandbox-setup.sh`, with a unit test holding them equal; until then, run the
   suite with the dockerised 0.9.0 shim.
5. **(a) — proposed (kp-uvy.18).** *Chainsaw verify keys on the exact commit, so
   every rebase forced a 15-minute re-run.* Key verifier and live evidence on a
   hash of the relevant trees, so a rebase that changes nothing they cover
   reuses the green run. Also branch-buildable GitOps (`gitops_revision`) so
   Composition/ApplicationSet changes can be proven before merge.
6. **(a) — proposed (kp-zab.9).** *Every worktree agent first hit the beads
   push guard.* Bootstrap beads in a worktree-create hook, or have the guard
   print the one command. The shared Dolt server (brief at
   `/home/claude/beads-shared-server-setup-brief.md`) removes the class.
7. **(a) — proposed (kp-zab.18, kp-zab.19, kp-zab.20).** *Driver and workflow
   rough edges found by builds:* backend race when ops box and base start
   together; `refresh.sh` fails after force-push; driver prints an empty body
   from a cached DNS miss.
8. **(c) — resolved by the owner.** *The auto-mode soft-deny "Blind Apply"
   blocked legitimate CI dispatches.* The owner removed the rule; recorded so a
   future block is diagnosed from `permissionDecision.classifierCategory` and
   the settings-file timeline, as done here.
9. **(c) — open (kp-zab.7).** *CI cluster-access checks run with admin
   credentials* by owner choice; tightening is a structural change.
10. **(d) — observation.** *A client-side failure masqueraded as server evidence*
    (`openssl -tls1_1` fails locally with "no protocols available"). Caught
    before it became a claim; the existing "label claim strength" rule covers it.
11. **(d) — observation.** *Coordinator mistakes caught in-session:* wrong bead
    ID quoted to the owner (.38 vs .36); kp-2al.36 closed before its live proof
    (reopened); a `git checkout` to drop a debug line reverted a new test; a test
    shim overwrote and deleted the suite's existing `getent` mock; chainsaw
    dispatched before the unit run finished; a nonsense timestamp ("~00:61Z") and
    a gendered pronoun written into records (both fixed before merge). Each cost
    minutes, none reached `main`; no rule would have prevented them better than
    the reviews that caught them.
